01mx-conformancePython, Apache 2.0

MXGOLD

A bit-exact golden reference for OCP Microscaling arithmetic at the operation layer: scaled blocks, dot products and accumulators, not just single-element encode and decode.

Conformance checks
43/43
Runtime dependencies
0
CI matrix
3.10to 3.13
  • policy.py

    Makes the spec's open choices explicit: OverflowPolicy, RoundingMode, SubnormalPolicy, AccumulationOrder, ScaleSelection.

  • formats.py

    Element formats E4M3, E5M2, E2M1 and INT8, plus E8M0 scales. encode() returns raw bit patterns, so −0.0 and NaN payloads stay distinct.

  • block.py

    Block formats MXFP8, MXFP4 and NVFP4: select_scale, quantize_block, dot_product with a clamped accumulator, and fma.

  • test_conformance.py

    43 checks, run by GitHub Actions on Python 3.10 to 3.13. Unconfirmed readings are tagged [UNVERIFIED] in the code.

Gap A

E4M3 overflow: saturate to 448.0 or produce NaN. Both conform.

Gap B

MXFP4 vs NVFP4: same element bits, different block size and scale encoding.

Gap C

Scale selection is unspecified. Not previously documented.

02riscv-pipelined-coreVerilog, Sky130

RV32I CORE

A 4-stage pipelined RV32I subset core with forwarding, load-use stalling and branch squashing, verified against a from-scratch golden model and signed off to GDSII.

333MHz

Core area

  • riscv_core.v

    Pipeline registers, forwarding muxes, the hazard unit and branch resolution in EX.

  • alu.vregfile.v

    ADD, SUB, AND, OR, XOR, SLL, SRL, SLT and immediates; 32-entry register file.

  • imem.vdmem.v

    Harvard memories: instruction ROM via $readmemh, data RAM with synchronous write.

  • golden_model.pytb_riscv_core.v

    A from-scratch RV32I interpreter, not a port of the RTL, checks final registers for programs that each target one hazard.
